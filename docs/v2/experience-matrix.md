# LivingBot 2.0 experience acceptance

2026-11-20 scope correction: the user rejected the replacement frontend and
explicitly removed Creative/Expert modules and their dedicated implementations.
Rows E26–E33 below are historical implementation records, withdrawn as product
requirements and acceptance claims; do not use them to authorize more work.
Ordinary file delivery, native tools, group assignments/private reports and
GitHub ability sharing remain required. The selected frontend is the existing
1.0-derived incremental design. Avatar, Bot-section, pinning and settings
inheritance must be verified against that frontend, not replacement screenshots.
The earlier complete-matrix acceptance is reopened in feature_list.json.

This is the retained acceptance baseline, not a declaration of parity. “Partial”
means a lower layer has evidence but the complete user workflow does not.
“Pending” means the workflow is required and has not been demonstrated.
Reviewed WorkBuddy mechanisms and available reference code/specifications are
the reuse baseline. The earlier blanket exclusion of source reuse is superseded
by the user's source-first direction. This matrix does not establish source
provenance; vendor reference material stays in ignored local storage. New
features/modules requiring 100% independent implementation need explicit user
approval first. No requirement is removed by this change.

## Evidence and acceptance rules

Deterministic tests establish structured contracts and observable side effects.
They do not establish semantic quality or full user experience. Native integration
uses a real official runtime with a synthetic local model; it establishes protocol
behavior rather than the intelligence of a configured real model. Semantic
acceptance uses an opt-in provider-neutral LLM judge and a versioned rubric
calibrated against reviewed examples; judge errors are unqualified.

The feature tracker retains all requirements until the corresponding complete
workflow is demonstrated. No row may be removed or declared irrelevant merely
because implementation is difficult. Additional discovered workflows extend this
matrix. Personal source inventories, local screenshots and runtime evidence stay
in ignored local storage. This public matrix uses synthetic examples only.
