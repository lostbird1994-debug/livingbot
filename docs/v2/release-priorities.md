# LivingBot 2.0 首发优先级与后续路线图

2026-11-21 最新安排：先对照 1.0 恢复当前日常界面的遗漏，整批交由
WorkBuddy 实现，Codex 统一验收，最多三轮反馈后接手未解决项。新会话和
会话历史、原有聊天用量统计、桌面一体化窗口控制，以及查出的搜索、已读、
消息和文件入口缺接属于本轮恢复范围。其余已记录的高级能力整理为后续升级，
今晚不扩建。原有聊天用量栏必须恢复；下文的费用分析和预算提醒才是后续项。
正式资料迁移仍由用户显式发起，代码安装与资料迁移分别验收。

2026-11-20 用户纠偏优先：以现有基于 1.0 修改的增量前端为准，适配新后端，
补回头像、Bot 分区、置顶和设置等现有体验。当前另做的 workbench-web 界面
不作为最终交付。创作、专家及其专用流程代码已按用户要求移除，不再是首发或
后续必做项目；下文旧条目中的 E26–E33、s6-creative、s6-experts 引用已撤销。
通用技能、文件交付、群内协作与 GitHub 能力分享保持原有范围。

首要目标：尽快交付可安装、可实际工作的本地 2.0。原生 OpenClaw
已有的功能优先接入，不为追求自行实现而复制内核。必要适配围绕用户能观察到的
行为展开；正常使用、重启和已发现问题优先验证，不继续扩展假设性故障研究。

本文件安排交付顺序，不宣称相关功能已完成。原始需求、八阶段实施范围和
完整体验验收清单继续保留在 `feature_list.json`、`task.json` 和
`experience-matrix.md`。首发候选版交付与八阶段全部完成必须分别报告。

## 首发主线

1. **真正使用原生内核。** OpenClaw 是唯一执行内核；正常状态来自官方事件，
   不靠周期性查询猜测。私聊、连续对话、队列、正常重启后消息保留、任务停止、
   失败提示与明确续跑路径必须能实际使用。
2. **独立桌面版。** 安装、启动和资料目录与 1.0 分开，浏览器共享同一产品逻辑；
   不依赖旧桥接、云电脑、虚拟机或旧应用市场。
3. **保留核心工作体验。** 有序流式回复、过程折叠、工作中追加指令、提问与审批、
   附件、真实文件交付、后台任务、工作记录、通知、定时工作继续属于主线。
   不能以“加快上线”为由静默取消已经要求的 WorkBuddy 体验。
4. **八个 Bot 的连续性。** 身份、记忆、能力能够预览并迁移；正式导入由用户显式
   发起，先有可校验备份，1.0 原数据保持可用。保留同一 Bot 的跨会话回忆边界。
5. **本地协作与统一能力入口。** LivingBot 内部群聊与私聊区分、群任务分别汇报、
   允许的历史上下文可查询；能力统一管理，工作区和交付路径有统一规则。
   Codex/WorkBuddy 继续保留为可调用能力的方向，按用户最新安排，其配置入口
   放到首发后完成，不阻塞本轮上线；它们不成为第二套主内核。
6. **可使用的新界面和分享入口。** 统一组件、图标、配色和简单可点击全景；
   GitHub 能力包的查找、安装、管理、导出分享使用同一产品流程。
   首发不以市场商业化或复杂视觉演出为前提。

以上是首发应推进的工作，不是当前完成清单。已知影响正常使用的错误不能以
“以后优化”为由隐藏；未完成能力必须准确标识。

## 后续工作的建议顺序

以下是待实施建议，不代表当前已具备，也不增加首发阻塞项。优先从实际使用中
发现的问题安排工作，不为覆盖所有可能性提前建设。

### 首次可用发布之后优先考虑

1. **记忆可解释、可纠正。** 让用户查看 Bot 记住了什么、来自哪段对话，并纠正
   过时事实；沿用官方记忆能力提供产品入口。比继续研究罕见恢复场景更直接地改善
   日常使用。其他 Bot 的私聊不因此自动互通。
2. **工作成果可查、可复用。** 在已有统一目录和文件交付基础上，增加按任务查看
   成果、定位最新版和另存修改版本。先解决真实的找文件、认版本问题，再考虑更完整
   的历史管理；不自动整理或搬动既有用户资料。
3. **能力更新与回退。** GitHub 安装和导出分享之后，补充更新内容预览、保留本地
   定制、返回上一能力版本；Bot 分享包默认排除私聊、个人记忆和密钥。先把能力分享
   做好用，再建设自动审核与复杂市场运营。
4. **协作过程更清楚。** 在群任务、私聊汇报和必要上下文可查询已经可用后，再提供
   谁负责、谁在等待、成果在哪里的集中视图，减少反复追问；不新增独立的执行状态源。
5. **模型用量和费用可见。** 优先使用内核或服务实际返回的用量；费用仅在已配置价格
   时估算并明确标识。先帮助用户判断消耗来自哪里，再按需要增加预算提醒和模型选择，
   不提前制作复杂自动路由。

### 有实际需求再继续深化

- 更丰富的 Bot 全景、空间布局和视觉动效：依据真实使用反馈选择设计，避免美术探索
  阻塞正常工作。
- 手机访问、跨设备使用和更多系统支持：本地桌面稳定后，再按需求验证相应权限、
  连接方式和适用流程。
- 精细记忆撤销、复杂灾难恢复、极端并发和故障组合：保留为明确的增强项，
  优先复用官方能力；已知会丢数据或阻断正常使用的问题仍须及时修复。

核心 WorkBuddy 交互、正常会话和重启、八 Bot 迁移、本地群聊、统一能力入口及
工作区规范不因上述后续安排降级。后续清单不等于八阶段全部完成。

## 不再分散首发精力

- 没有实际接入需求的自研内核功能，先查官方功能和支持接口。
- 不提前建立复杂兼容层、通用框架或多套并存的执行系统。
- 不反复验证已经通过且没有变化的路径；围绕新修改和真实失败补检查。
- 云电脑、虚拟机、Cursor/xAI 旧应用市场不进入后续路线图，它们已明确不属于产品方向。

## 当前执行顺序

独立桌面包与启动配置 → 正常聊天和重启主流程 → 八 Bot 迁移入口与能力使用 →
群聊汇报与交付串联 → 首发界面和安装验收。修复这些流程中实际发现的问题；
增强型记忆还原研究不再占据主线。
