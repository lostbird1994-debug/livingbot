# 批量处理

> 方法说明：本方法按既有办公/创作技能规范改写（规范改编），工具契约以本插件注册的原生工具为准。


先明确用户选定的输入集合、输出位置和每项成功的可观察条件。保留原件，
使用任务或项目目录中的清单记录稳定的输入标识、源版本或摘要、目标文件、
状态、错误和真实结果回执。少量一次性任务使用简单清单即可，不搭建新队列。

每项完成后更新清单，成功状态以实际文件、校验结果或服务回执为依据。
重试前重新读取清单及目标结果，只重做失败或尚未处理的项；源内容变化时
将其作为新版本处理。请求已发出但回执丢失时，先查询实际结果，不盲目重发
可能产生重复记录的写操作。需要外部写入时沿用用户给定的对象与授权范围。

独立项目可并行，保持结果与输入逐项对应。某项失败不抹去其他已完成的结果；
报告成功、失败和待确认项以及继续入口。交付结果文件与必要的失败清单，
用 livingbot_deliver_file 提供实际文件，不把“脚本运行结束”当作整批成功。

## 输入检查

先确认批次规模、每一项的输入、统一命名规则和“部分失败怎么办”。
批量前先取一项跑通，再放开整批；不要把未验证的模板套到几十个文件上。
明确哪些项会覆盖已有文件——默认不覆盖，冲突项单独列出。

## 步骤

1. 建清单：每项一行，写清输入、预期输出名、是否已存在同名文件。
2. 单件试跑：先做一项，核对结果与命名，再批量。
3. 批量执行：逐项记录成功/失败/跳过，失败项附原因，不吞掉错误。
4. 汇总：交付一张结果表（项名、状态、输出路径、备注），失败项给出下一步。

## 交付格式

- 结果表与文件一起交付；文件名统一规则在回复里说明一次。
- 部分成功时明确写“已完成 N 项，失败 M 项”，不把部分成功说成全成。

## 边界

- 不静默跳过失败项，不重复生成覆盖已完成项。
- 不在批次中途改变命名规则或输出目录。
- 大批量先报总量与预计产物数量，避免刷屏聊天。
